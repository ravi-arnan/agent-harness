agent-harness

My agent behaviour, portable. One command puts the same rules, agents, skills and MCP setup onto any Ubuntu box, across opencode, Antigravity CLI and Claude Code.

Install

curl -fsSL https://raw.githubusercontent.com/ravi-arnan/agent-harness/main/install.sh | bash -s -- --profile office

Or from a clone, which is easier to inspect before running:

git clone https://github.com/ravi-arnan/agent-harness.git ~/agent-harness
~/agent-harness/install.sh --profile office

Profiles

office

A work machine with a company account. No personal provider keys, no local model router, no personal tunnels. opencode resolves its model from opencode auth login; Antigravity uses the company Google account.

personal

My own machine. Adds the local 9router provider, the free-provider keys under ~/.config/opencode/secrets/, and the laptop-specific thermal rules.

The installer writes the choice to ~/.config/harness/state.json and asks when --profile is omitted.

How it lands on the machine

Symlinked, so git pull is the whole update:

TargetSource
~/.claude/rules/ecclayer-ecc/rules
~/.claude/agents commands skills scriptslayer-ecc/*, scripts/claude
~/.config/opencode/router.md skills plugin bin tui.jsonlayer-personal/*, harnesses/opencode/*

Generated, because they differ per machine: ~/.config/opencode/opencode.jsonc, ~/.config/opencode/AGENTS.md, ~/.gemini/config/GEMINI.md, ~/.gemini/config/mcp_config.json, skills.json and hooks.json. Each is a portable base plus a profile overlay. Anything already at a link target is moved to ~/harness-backup-<timestamp>/ first, never deleted.

What is not in it

No credentials and no personal context. Specifically excluded: ~/.config/opencode/secrets/, auth.json, .credentials.json, .claude.json, oauth_creds.json, .git-credentials, auto-memory, session and telemetry data, and my machine identifiers. scripts/sanitize.mjs fails the build on all of them, and CI runs it on every push.

Values a machine needs, like a tunnel URL or a project ref, are {{TOKENS}} filled from ~/.config/harness/env (mode 600). When unset, the entry that needed it is dropped and reported instead of being written out broken.

After installing

opencode auth login                      # office account on the office box
opencode run "say hi"                    # proves the whole config loads
node ~/agent-harness/harness.mjs doctor  # binaries, links, missing secrets
node ~/agent-harness/harness.mjs status  # kit vs machine, exit 1 on drift

status is the one to run before and after a git pull. It checks all three harnesses, not just opencode.
